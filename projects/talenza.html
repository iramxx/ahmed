Talenza

AI-powered executive hiring intelligence platform.

Overview

Talenza is an AI-powered executive hiring intelligence platform built for a BMW hackathon. The core concept revolves around scenario-based ranking: the same candidate pool re-ranks differently depending on which strategic business scenario is active (Crisis, Transformation, Growth, Succession).

Target users are senior HR executive search teams hiring at the VP/SVP/board level. Traditional ATS tools rank candidates once, but Talenza models the reality that candidate fit is heavily context-dependent—a candidate ideal for a crisis is often wrong for a corporate transformation.

🏆 Built as a team effort during the BMW / Lovable Hackathon sprint. I owned the n8n workflow backend architecture.

Architecture Overview

The application is divided into two main layers: a powerful, locally-hosted workflow backend and an ultra-modern React frontend.

  • Layer 1 (AI Pipeline): An n8n workflow backend serving as an end-to-end agentic pipeline. It handles CV parsing, unstructured scenario input mapping, multi-dimensional scoring, and candidate cost analysis using the Anthropic Claude API.
  • Layer 2 (Frontend Interface): A React 18 frontend built with Vite, Tailwind CSS, and shadcn/ui. Initially deployed on Vercel with mock AI functions for rapid hackathon presentation, maintaining compatibility.

AI Engine & Agents

The core AI reasoning relies on four conceptual agents integrated into the pipeline:

  1. Candidate Profiler: Extracts competencies, character traits, and HR opinions into structured JSON profiles from raw CVs.
  2. Scenario Analyst: Converts raw free-text situations into structured scenarios. Evaluates missing context through sequential Q&A.
  3. Scoring & Strategy Agent: Produces rank scoring with specific reasoning bullets, calculating impact points across domains (fit, timeline, risk).
  4. Scenario Comparison Agent: Allows comparative ranking deltas when evaluating identical candidate cohorts under different organizational stressors.

Overall Score = (Scenario Fit × 0.3) + (Exp Match × 0.25) + (Leadership Fit × 0.2) + (Availability × 0.15) + ((100 - Risk) × 0.1)

Key Engineering Decisions

  • n8n Distributed Config: Webhook chains required isolated execution context forced inline configuration nodes rather than shared blocks. Node.js `fs` module usage explicitly whitelisted locally for file I/O operations.
  • Deployment Compromises: Serverless architecture (Vercel) cannot host persistent n8n automated flows natively, pushing towards local Docker Compose instances or Render for backend scale.
  • Prompt Abstraction: Kept API schemas provider-agnostic, designing Claude integration strictly to content block abstractions to ease transitioning to Gemini models in future iterations.
  • Three.js / 3D Graphics: Deployed an instanced Fibonacci sphere node mesh wrapped with breathing animations. Device pixel ratio strictly capped at 1.5 to maintain stable framerates on lower-end devices.
